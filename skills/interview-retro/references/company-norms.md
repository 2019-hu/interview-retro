# 公司性质 → 关注点、权重与忌讳

权重档案是**数据的**，存放在 assets/company-profiles.json（analyze.mjs 会把命中的档案直接带进 analysis.json，score.mjs 用它算加权分）。本文件解释「为什么这么配权重」，以及每类公司在表达上的忌讳。

| 类型 key | 常见对象 | 最看重 | 权重倾向 |
| --- | --- | --- | --- |
| bigtech | 一线互联网大厂 | 技术纵深、数据口径、抗压追问 | depth / evidence 高 |
| growth | 中厂、成长期公司 | 落地速度、独立负责、业务理解 | evidence / fit 高 |
| foreign | 外企、跨国团队 | 结构化表达、英文沟通、流程意识 | structure / delivery 高 |
| soe_finance | 国企、银行、金融科技 | 稳定性、合规意识、表达分寸 | delivery / fit 高，depth 中 |
| startup | 创业公司、早期团队 | 多面手、从 0 到 1、成本意识 | fit / evidence 高，structure 中 |
| outsourcing | 外包、驻场 | 快速上手、按规范交付、沟通配合 | delivery / structure 高 |
| research | 研究型岗位、实验室 | 论文与实验严谨性、方法深度 | depth 高 |
| general | 未知或混合 | 均衡评估 | 五维等权 |

## 各类别的判读要点

### bigtech（一线大厂）
- 关注：为什么这么设计、数据怎么来的、极值场景；对名词堆砌极其敏感。
- 表达：先结论后论证，允许被打断；别讲业务黑话，讲清技术因果。
- 忌讳：背答案、编数据、「我们团队」代替「我」。

### growth（中厂 / 成长期）
- 关注：一个人能不能扛事、上手速度、需求到上线的完整链路。
- 表达：给结果、给时间、给成本，展示你会算账。
- 忌讳：只讲框架不讲业务收益；过度强调规范流程（对方资源没那么多）。

### foreign（外企 / 跨国）
- 关注：结构化沟通、跨时区协作、书面表达、合规与边界感。
- 表达：结论先行，能被压缩成 30 秒版本；准备好英文复述核心项目。
- 忌讳：模糊承诺、含糊其辞的团队描述、对流程价值不以为然。

### soe_finance（国企 / 银行 / 金融科技）
- 关注：稳定可靠、风险与合规意识、长期服务意愿、表达分寸。
- 表达：少用夸张词（颠覆、绝对），多讲规范、审计、双人复核、变更流程。
- 忌讳：频繁跳槽的解释不到位、贬低前东家、过度炫耀「黑客式」做法。

### startup（创业公司）
- 关注：多面手、从 0 到 1、自己找活干、成本与速度。
- 表达：讲你如何在没有资源的情况下推进，讲你踩过并修好的坑。
- 忌讳：强调「我只做后端」这类边界；抱怨资源不足。

### outsourcing（外包 / 驻场）
- 关注：按规范交付、快速熟悉陌生系统、客户沟通与耐受力。
- 表达：讲清你怎么读别人的代码、怎么在约束下保证质量。
- 忌讳：表现出对「不是核心业务」的轻视。

### research（研究型）
- 关注：方法严谨性、实验设计、文献理解、复现能力。
- 表达：讲清假设、控制变量、统计显著性与局限性。
- 忌讳：把工程 go-live 故事当成科研贡献讲。

## 使用方式

1. 用户给了公司名但没给类型 → 先按名单推测并**明确告知是推测**，让用户确认后再落权重。
2. 跨类型公司（如大厂金融部门）→ 由用户指定主类型；报告里注明另一类型的影响点。
3. 权重只影响总分与「哪条短板最致命」，不用于给候选人贴标签。
