# 丢分归因表 G1-G6 与补齐动作库

先归因，再给动作。**误判归因比不归因更糟**：把「没做过」当成「讲不好」去练话术，练一个月也不会涨分。

## 归因判定流程

1. 看 analysis.json 里该题的 flags，确定丢的是**事实**还是**表达**。
2. 用下面六类的判定信号逐个排除。
3. 写出根因句：因为 ______，所以 ______，证据是「______」。
4. 从对应动作库选动作，且**必须带产出物与验收标准**。

| code | 名称 | 判定信号 | 根因性质 |
| --- | --- | --- | --- |
| G1 | 事实/经历缺失 | 没有相关项目；被问到直接说没用过；细节靠编 | 不可话术修复 |
| G2 | 结构缺失 | 有料但讲散了，flags 含 no_context / no_result / no_action；或结果只有形容词没有数字（no_quantification / hedge_heavy）；面试官反复追问背景 | 可快速修复 |
| G3 | 技术纵深不足 | 只会 what；追问一层即断；0 个取舍词 | 需 3-7 天补原理 |
| G4 | 岗位匹配错位 | jd.coverage 低；答得很技术但与 JD 关注点无关 | 可当天修复 |
| G5 | 表达损耗 | est_seconds > 240；重复、绕圈、被打断后答偏 | 可当天修复 |
| G6 | 反问与收尾 | 零反问或只问「加班多吗」；没问出团队真实状态 | 可当天修复 |

## 动作库（每条都要填「产出物 + 验收标准」）

### G1 事实缺失 —— 只有两条路：换素材，或补最小可讲项目

- 换素材：把问题按主题聚类，从已有经历里找出**结构同构**的替代案例（例如没做过分库分表，就讲读多写少的缓存分层 + 数据量增长下的取舍）。产出物：替代案例卡（场景/约束/动作/结果/代价）。
- 补最小项目：选 1 个与 JD 高频要求交集最大的缺口，做一个能跑起来的最小实现（本地能复现、有压测或基准数据）。产出物：可演示仓库 + 一页数据结论。
- 验收标准：能脱稿 90 秒讲完该案例，并能挡住「为什么不用 X」与「数据怎么来的」两层追问。
- 红线：**不要虚构项目**。编造的细节在第三层追问必然崩塌。

### G2 结构缺失 —— 用同一模板重讲，直到 90 秒内可复述

- 模板 A（行为题，STAR-L）：背景一句话 → 我的唯一目标 → 三个动作（各一句）→ 结果数字 → 学到什么。
- 模板 B（技术题）：结论 → 约束条件 → 两个候选方案 → 选择的代价 → 线上验证数据。
- 模板 C（故障题）：影响面 → 时间线（发现/定位/恢复）→ 根因 → 修复 → 防复发机制。
- 产出物：每题一页「骨架卡」（只写关键词，不写逐字稿），一次 90 秒计时练习录音。
- 验收标准：连续两遍都在 90 秒内讲完，且第二遍不看卡片。

### G3 纵深不足 —— 用「三层追问法」补

- 第 1 层 what：它是什么、解决什么问题。
- 第 2 层 why：为什么选它而不是替代方案，代价是什么。
- 第 3 层 failure：什么条件下会失效，怎么发现、怎么兜底。
- 产出物：每个被追问的技术点一张三层卡 + 一个可复现的小实验（能跑出数据或看到边界）。
- 验收标准：能主动说出「它在什么规模/什么流量下会崩」并给出监控指标。

### G4 匹配错位 —— 把经历翻译成 JD 的语言

- 动作：用 references/jd-alignment.md 的方法，把 JD 拆成「硬技能 / 业务语境 / 软性要求」三列，把每条经历的标题改写成对应列的说法。
- 产出物：一页对齐表（JD 要求 ↔ 我的证据 ↔ 一句话口径）。
- 验收标准：analysis 的 jd.coverage 提升到 0.7 以上，且每个高频关键词都能举出场景。

### G5 表达损耗 —— 计时 + 收敛句

- 动作：给每题准备一句「收敛句」（「这块核心是 X，要不要我展开 Y 部分？」），练习被打断后 5 秒内切到被问的点。
- 产出物：收敛句清单 + 3 次计时录音（目标 90-150 秒）。
- 验收标准：单题时长落入 90-150 秒区间的比例 >= 70%。

### G6 反问与收尾 —— 准备三类有效反问

- 团队现状类：「团队现在最想解决的技术债是什么？」
- 岗位期望类：「这个岗位前三个月最重要的产出是什么，怎么算做得好？」
- 决策机制类：「技术方案一般由谁拍板，怎么处理分歧？」
- 产出物：反问清单（按面试官角色分：技术面 / 主管面 / HR 面）。
- 验收标准：每场至少问 2 个非薪资类问题，并能在报告里写出从回答里听到的信息。

## 合并规则（避免流水账）

- 同一 code 出现 >=3 次：只保留 2 条最典型的，其余合并成一句「本场共 N 题属于同类问题」。
- 报告正文最多列 3 大短板；第 4 条起进附录表。
- 优先修「高权重维度 + 高频 gap」的交集，而不是修最多条目的那个。
